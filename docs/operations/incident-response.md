# 侵害の対応

掲載中のプラグインの作者のアカウントが乗っ取られた疑いや、悪意のある版が掲載された疑いがあるときの手順です。本サービスは配布物を預からず、GitHub のリリースへ案内するだけです。そのため、本サービスにできるのは、案内を止めること、影響を受けた版と期間を知らせること、作者と GitHub へ連絡することです。配布物そのものは消せません。

対応の順序は、利用者への被害を広げないことを先にし、原因の調査を後にします。

## 対応の流れ

1. 版を止める: 疑いのある版を、調査の前に止めます。プラグイン全体を止める必要があれば、[掲載停止と再開](suspend.md) の `suspend` も行います。

   ```sh
   npm run admin -- suspend-release <owner/repo> <tag> "<告知の文>" --remote
   ```

   止めた版は、告知ページ `<ORIGIN>/notices` と、そのプラグインの詳細ページと `get_plugin` の警告に表示されます。告知の文には、公開してよい範囲の内容だけを書きます。

2. 影響を確かめる: 止めた版の配布物の SHA-256 と掲載の期間を確認します。

   ```sh
   npm run admin -- show <owner/repo> --remote
   ```

   出力の `listing_periods` に、版ごとの配布物と掲載を始めた日時・終えた日時が出ます。この期間に本サービスからダウンロードした利用者が影響を受けた可能性があります。

3. 作者へ連絡する: 作者のリポジトリの Security の Private vulnerability reporting、それが無ければ README などに書かれた連絡先へ、止めた版・理由・確認してほしいことを伝えます。アカウントの乗っ取りの疑いがある場合は、公開の Issue に書きません。

4. GitHub へ通報する: 悪意のある配布物が GitHub のリリースに残っている場合は、GitHub の Report abuse から、リポジトリの悪用として通報します。本サービスは配布物を消せないため、GitHub から直接ダウンロードする人を守るにはこの通報が要ります。

5. 告知を更新する: 調べてわかったこと (影響を受けた版、期間、利用者にしてほしいこと) を、告知の文に書き足します。

   ```sh
   npm run admin -- suspend-release <owner/repo> <tag> "<更新した告知の文>" --remote
   ```

6. 収束を判断する: 作者がアカウントを取り戻し、悪意のある版を取り下げ、新しい版を出したら、新しい版は通常の検査を通って掲載されます。止めた版の記録と告知は残します。

## 利用者へ伝えること

告知の文には、次を含めます。

- 影響を受けたプラグイン・版・配布物の SHA-256
- 本サービスで掲載していた期間
- 利用者にしてほしいこと (該当の版のフォルダーを OBS Studio のプラグインのフォルダーから削除する、ウイルス対策ソフトでスキャンする、など)

推測で原因や被害の範囲を書きません。わかっていないことは、調査中と書きます。

## 記録

止めた版と告知は `release_suspensions` に、掲載した配布物と期間は `listing_periods` に残ります。どちらの表も、プラグインやリリースの削除と連鎖せず、行を削除しません。表の定義は [データモデル](../design/data-model.md) に記載します。
