# 画面構成

Web カタログの画面の一覧と、各画面に置く要素の仕様です。Web カタログは閲覧専用で、プラグインの登録は MCP の `submit_plugin` だけで受け付けます。

## 共通の仕様

| 項目 | 仕様 |
| --- | --- |
| スクリプト | 使わない。検索はフォームの送信で行う |
| 出力の無害化 | Hono の JSX の自動エスケープを使い、生の HTML を出力しない |
| 応答ヘッダー | `Content-Security-Policy` は `default-src 'none'` を基本とし、スタイルシートと画像とフォームの送信先を自サイトに限る。`X-Content-Type-Options: nosniff`・`Referrer-Policy: strict-origin-when-cross-origin`・`X-Frame-Options: DENY` を付ける |
| プラグインの名前 | `.soko-kun/config.json` の `name` を表示する。無ければリポジトリ名を表示する。外部データとして扱う |
| 外部データ | 概要は画面の言語へ機械翻訳して表示し、自動翻訳である旨を添える。詳細ページには原文を表示するリンクも添える。配布物名は GitHub の原文のまま表示する。リリース名は画面に出さない |
| 示す版 | 掲載対象バージョンだけを示す。それより新しく検査済みでないリリースは示さない |
| リンク | 本文と固定ページに書く URL は、すべてリンクにする。置き換え用の語 (`<owner>` など) を含む例の URL はリンクにしない |
| 固定ページの書式 | コマンドはコードブロックで示す。並列の条件や一覧は箇条書きで示す |
| 掲載の範囲 | 一覧に出すのは掲載中のプラグインだけ |
| モバイル表示 | 幅 760 px 以下で 1 段組みに切り替える。幅 320 px まで、画面の右端からはみ出す要素を作らない |
| スクロール | 画面全体の縦方向のスクロールだけを使う。要素の中のスクロールと横方向のスクロールは使わない |

## 見た目の方針

2000 年代前半のソフトウェア紹介サイトの見た目に合わせます。特定のサイトの模倣はしません。

| 項目 | 仕様 |
| --- | --- |
| 幅 | 本文と右の列を、最大幅 860 px で中央に寄せる |
| 文字 | 基本の大きさは 13 px。見出しは 17 px、注記は 11 px |
| 見出しの帯 | 上部の帯と右の列の見出しは、主の色のグラデーションで塗る。本文の見出しの帯は副の色で塗る |
| 罫線 | 区画は 1 px の灰色の罫線で囲む。角は丸めない |
| リンク | 下線を付ける |
| ボタン | 上と左を明るく、下と右を暗くした立体的な枠で描く。ダウンロードボタンだけを主の色で塗る |
| 検索ボタン | 虫眼鏡の図だけを表示する。図は HTML に直接書いた SVG で描き、読み上げ用の文字を見えない形で添える |
| 上部の帯の部品 | 検索欄、検索ボタン、言語のボタンを同じ高さにし、縦の中央でそろえる |
| 暗い配色 | ブラウザの設定 (`prefers-color-scheme`) に従って、明るい配色と暗い配色を切り替える。画面上の切替えは置かない。暗い配色でも「配色の規則」を保ち、テーマカラーを背景に使う場所を減らして、文字にはテーマカラーを明るくした色を使う |
| 文字と背景 | 本文の文字と背景の組み合わせは、明るい配色と暗い配色のどちらでも、コントラスト比 4.5 以上にする |

## 配色の規則

色は、2 つのテーマカラーと、白・灰・黒の無彩色だけを使います。カテゴリのタグもテーマカラーで表示し、カテゴリごとに色を分けません。

| テーマカラー | 値 | 使う場所 |
| --- | --- | --- |
| 主の色 (赤紫) | `#250213` | 上部の帯、右の列の見出し、ダウンロードボタン、カテゴリのタグ、本文の見出しの帯の左の罫線 |
| 副の色 (淡い橙) | `#e2c69c` | 本文の見出しの帯、選んでいるカテゴリ。ダウンロードの枠と注意書きの背景には、副の色を淡くした色を使う |

本文の見出しの帯・ダウンロードの枠・注意書きの罫線と、注意の文字には、副の色を暗くした色を使います。リンクの文字は、主の色と同じ色相で明るくした `#8b1850` で表示します。主の色はほぼ黒に近く、そのままでは本文の黒い文字と見分けにくいためです。暗い配色では、主の色の背景が画面の背景に溶けないよう、帯を主の色と同じ色相で明るくした色で塗ります。リンクの文字には、同じ色相の淡い色を使います。

注意書きは、副の色の背景に太い枠線と「注意」の見出しを付けて、ほかの情報と区別します。

例外の色は次の 1 つで、安全に関わる表示に限ります。

| 色 | 使う表示 | 理由 |
| --- | --- | --- |
| 赤 | 掲載停止と掲載終了の状態 | 利用者に危険の表示を見落とさせないため |

新しい色を加えるときは、この表に色・使う表示・理由を書き足してから使います。

## 文言の規則

画面と固定ページの文言は、次の規則で書きます。

- 主語を文頭に置き、主語と述語の対応を明らかにする。
- 利用者に求める行動は「〜してください」と書く。
- 1 つの文には 1 つの主張を入れる。事実だけで終わらせず、その事実を理由に利用者が取るべき行動まで 1 文で書く。
- 日本語の文言は yomiyasu で推敲する。ほかの言語の文言は、推敲した日本語の意味に合わせて書く。

全ページ共通の注意書きは、次の 2 文です。

> このプラットフォームは OBS Project と無関係の非公式で無料のサービスです。各プラグインの安全性を保証しないので、個人の責任にもとづき注意して利用してください。

配布物を GitHub から直接ダウンロードすることは、注意書きには書かず、「配信プラグイン倉庫くんとは？」のページとダウンロードボタンの近くに書きます。

## 画面の一覧

| パス | 画面 |
| --- | --- |
| `/` | トップと検索 |
| `/?q=...&os=...&category=...` | 検索結果 |
| `/?category=...` | カテゴリ別の一覧 |
| `/plugins/<owner>/<repo>` | プラグインの詳細 |
| `/notices` | 告知ページ。「告知ページ」を参照 |
| `/about` | 配信プラグイン倉庫くんとは？ |
| `/policy` | 掲載ポリシー |
| `/submit` | プラグインを登録する (作者向け) |
| `/security` | セキュリティと免責 |
| `/report` | 通報の案内 |
| `/terms` | 利用規約 |
| `/privacy` | プライバシーポリシー |
| `/robots.txt` | 検索エンジン向けの指定 |
| `/sitemap.xml` | サイトマップ。トップ・全固定ページ・掲載中のプラグインの詳細ページを 7 言語分載せる |
| `/plugins/<owner>/<repo>/logo`・`/plugins/<owner>/<repo>/image`・`/plugins/<owner>/<repo>/preview` | プラグインのロゴ、説明の画像、説明の画像の表示用の WebP の配信。「プラグインの画像」を参照 |
| `POST /contact` | 開発者の連絡先の表示。「全ページ共通の枠」を参照 |
| `/og.png` | 共有のときの共通画像 (1200 x 630 px)。「検索エンジンと共有のときの表示」を参照。`public/` の静的アセットとして Worker を通さずに配信する |
| `/logo.svg` | サービスのロゴ。ファビコンにも使う。URL のクエリに内容のハッシュを付ける |
| `/logo.png` | サービスのロゴの PNG (256 x 256 px)。SVG を表示できない場所 (MCP のサーバーの一覧のアイコンなど) に使う。`public/` の静的アセットとして Worker を通さずに配信する |
| `/style.css` | スタイルシート。URL のクエリに内容のハッシュを付け、変わったときに閲覧者のキャッシュを使わせない |

`/og.png` と `/logo.png` は `public/` に PNG のファイルとして置き、Workers の静的アセットで配信します。画像を base64 の文字列でソースに埋め込むと、ソースを読む人や検査の道具が中身を確かめられないためです。キャッシュと `X-Content-Type-Options` は `public/_headers` で指定します。

詳細ページの `?orig=1` は、概要を原文で表示します。一覧の `?page=` は、ページ送りのページ番号です。`/robots.txt` は、すべてのページの収集を許し、`/mcp` だけを除外して、サイトマップの URL を示します。

## 全ページ共通の枠

画面は、上から順に次の要素で構成します。

| 要素 | 内容 |
| --- | --- |
| 上部の帯 | サービスのロゴ・サービス名・キーワードの検索欄・言語の一覧。ロゴは「サービスのロゴ」を参照 |
| カテゴリの帯 | 左端にすべての一覧へのリンクを置き、その右にその他を除く 6 カテゴリを並べる |
| 注意書き | 「文言の規則」に書いた 2 文 |
| 本文 | 各画面の内容。右の列を除いた残りの幅 |
| 右の列 | 幅 230 px。内容は下表 |
| 下部 | 固定ページへのリンク、本サービスのソースコードへのリンク、注意書きの 2 文、「連絡先を表示」ボタンとその右の開発の支援 (GitHub Sponsors) のボタン、「© 2026 AllegroMoltoV」の表記 |

開発の支援へのリンクは、下部と `/about` の「開発の支援」の節にだけ置きます。下部では、ハートの記号を添えた角の丸いボタンの形にします。右の列や本文の目立つ場所には置きません。支援への見返りは設けず、支援の有無はプラグインの掲載と検査に影響しません。

開発者の連絡先のメールアドレスは、収集されてスパムが届くことを防ぐため、ページの HTML に書きません。下部と、通報・利用規約・プライバシーポリシーの連絡先の節には、「連絡先を表示」ボタンを置きます。ボタンはフォームの送信で、押したときだけ、サーバーが `@` を `[at]` に置き換えたアドレスを返します。スクリプトは使いません。アドレスは Worker の環境変数 `CONTACT_EMAIL` に置き、ソースコードと docs には書きません。

右の列には、本文と重ならない情報を置きます。幅 760 px 以下の表示では、右の列を本文の下へ移し、各区画を閉じた状態で表示します。区画の見出しを押すと開きます。スクリプトを使わないため、右の列は幅の広い画面用と狭い画面用の 2 通りを出し分けます。

| 区画 | 内容 |
| --- | --- |
| 新着 5 件 | 掲載中のプラグインを、このプラットフォームに登録した日の新しい順に 5 件。名前・カテゴリ・登録日。掲載中のプラグインが無いときは、区画を出さない |
| 週間 DL 数ランキング 5 件 | 掲載中のプラグインを、過去 7 日間のダウンロード数の多い順に 5 件。名前と数。週間の数を求められないプラグインと、数が 0 のプラグインは出さない。出すプラグインが無いときは、区画を出さない。数は GitHub での全ダウンロードである旨を添える |
| AI エージェントから使う | MCP で接続すると会話でプラグインを探せること、OBS Studio のプラグインの作者は会話で登録できること、話しかけ方の例、`/about` の接続方法へのリンク |
| 掲載と検査について | 作者本人が登録すること、配布物を既知のマルウェアのデータベースと照合すること、検出なしは安全の保証ではないこと、`/policy` と `/report` へのリンク |
| プラグインを登録する | 作者向けに、`/submit` への案内 |
| 倉庫の状況 | 掲載中の件数と、GitHub の情報の確認日時。確認日時は、定期処理が掲載中のプラグインを最後に同期した日時 |

幅 760 px 以下の表示では、右の列を本文の下へ移します。カテゴリの帯は折り返して表示します。上部の帯では、サービス名の下の行に検索欄と言語のボタンを並べます。言語の一覧は、開いたときに本文の上へ重ねず、帯の中に広げて表示します。注意書きは短縮し、詳細へのリンクを添えます。

## カテゴリ

| 表示名 | `category` の値 |
| --- | --- |
| 音声フィルター | `audio-filter` |
| 映像フィルター | `video-filter` |
| 入力ソース | `source`。配信画面に映像や音声を足すもの |
| トランジション | `transition` |
| ドック・パネル | `dock-ui`。OBS Studio の画面にドックやパネルを足すもの |
| 配信・録画 | `output` |
| その他 | `other`。どれにも当たらないもの |

カテゴリは、作者が登録のときに選びます。選ばなかった場合は自動で推定し、管理者は管理コマンドで直せます。OBS Forums のリソースの分類は OBS Studio Plugins の中を種類で分けていないため、OBS Studio の画面で使う言葉で分けています。カテゴリはテーマカラーのタグで表示します。推定の規則は [検査と同期](scanning.md) に記載します。

## トップと検索

| 要素 | 内容 |
| --- | --- |
| 検索フォーム | キーワードの入力欄と、OS とカテゴリの選択。OS の選択肢はすべて・Windows・macOS・Linux |
| 新着・更新 | 掲載中のプラグインのカード。並び順とページ送りは「検索結果とカテゴリ別の一覧」と同じ |

プラグインのカードは、ロゴ・名前・掲載対象バージョン・カテゴリのタグ・対応 OS のタグ・概要・作者・更新日・ダウンロード数を表示します。更新日は、掲載対象バージョンの公開日です。概要が自動翻訳のときは、自動翻訳である旨を短く添えます。原文を表示するリンクは詳細ページに置きます。ダウンロード数の記録が無いプラグインでは、ダウンロード数を表示しません。ロゴが無いプラグインでは、ロゴの場所を空けずに表示します。カードには状態のバッジを出しません。

## 検索結果とカテゴリ別の一覧

| 要素 | 内容 |
| --- | --- |
| 見出し | 検索語またはカテゴリと、件数 |
| 絞り込み | OS とカテゴリ |
| 並び順 | 掲載対象バージョンの公開日の新しい順 |
| 一覧 | トップと同じ形のカード |
| ページ送り | 前へ・現在のページと総ページ数・次へ。1 ページは 20 件 |

## プラグインの詳細

詳細ページの表示は、プラグインの掲載状態で決まります。状態ごとの公開範囲は [データモデル](data-model.md) に記載しています。検査待ちのプラグインの詳細ページは、未登録のプラグインと同じく 404 を返します。

プラグインの所有者名かリポジトリ名が GitHub で変わると、URL の ID も変わります。変わる前の ID の詳細ページは、新しい ID の詳細ページへ 301 で転送します。

掲載中のプラグインの詳細ページは、上から順に次の要素で構成します。

| 要素 | 内容 |
| --- | --- |
| パンくずリスト | ライブラリとカテゴリ |
| 見出し | ロゴ・名前・カテゴリのタグ・概要。掲載中であることは表示しない。一覧と詳細には掲載中のプラグインしか出ないため |
| 止めた版の警告 | 管理者が止めた版、またはマルウェアを検出した版があるときだけ表示する。内容は「止めた版の警告」を参照 |
| 説明の画像 | 作者が用意した画像 1 枚。表示用の WebP で表示し、GIF は押したときにアニメーションとして再生する。画像が無いプラグインでは表示しない |
| ダウンロードボタン | GitHub の配布物へ直接リンクする。掲載対象バージョン・配布物名・サイズを添える |
| 基本情報 | 作者・対応 OS・ビルドに使った OBS の版・ライセンス・バージョンと公開日・コミット SHA・GitHub リポジトリへのリンク・GitHub のリリース一覧へのリンク・ダウンロード数 (GitHub) と集計日 |
| 配布物と検査 | 配布物ごとの名前・SHA-256・検査結果・検査日時。スキャナーごとの結果。検出なしは安全の保証ではない旨 |
| 注意事項 | 配布物は作者が GitHub で公開したものであること、導入前に作者の説明を読むこと |
| 通報 | `/report` へのリンク |

作者が `.soko-kun/config.json` の `os` で対応 OS を宣言したプラグインでは、宣言した OS の配布物だけをダウンロードボタンと「配布物と検査」に表示します。推定の規則は [検査と同期](scanning.md) に記載します。

ビルドに使った OBS の版は、掲載対象バージョンのリリースの `buildspec.json` から取得した値です。値が無い場合は、確認できない旨を表示します。ダウンロード数は、新しい順に最大 100 件のリリースの配布物の、GitHub でのダウンロード数の合計です。このサイトを経由したものに限らない旨を添えます。記録が無い場合は、ダウンロード数の行を表示しません。

右の列には、全ページ共通の区画の前に、この作者のプラグインと、同じカテゴリのプラグインを掲載対象バージョンの公開日の新しい順に置きます。候補は掲載中のプラグインのうち公開日の新しい 200 件で、それぞれ最大 5 件です。この作者の欄に出したプラグインは、同じカテゴリの欄に出しません。

停止と掲載終了のプラグインの詳細ページは、次の要素だけで構成します。ロゴ・説明の画像・ダウンロードボタン・概要・配布物と検査の区画は表示しません。応答には `X-Robots-Tag: noindex` を付け、検索エンジンに載せません。

| 要素 | 内容 |
| --- | --- |
| パンくずリストと見出し | 名前・カテゴリのタグ・状態のバッジ (掲載停止、掲載終了) |
| 案内文 | 停止では、掲載を停止している旨。掲載終了では、GitHub で公開されなくなった旨 |
| 理由 | 停止で、管理停止の理由が設定されている場合だけ表示する |
| 止めた版の警告 | 停止で、止めた版があるときだけ表示する |
| 通報 | `/report` へのリンク |

右の列には、全ページ共通の区画だけを置きます。

### 止めた版の警告

止めた版は、管理者が止めた版と、マルウェアを検出した版です。どちらも `release_suspensions` に記録されます。警告には、止めた版ごとに、版・配布物の SHA-256・本サービスで掲載していた期間・告知の文を表示します。表示する内容は、告知ページの同じプラグインの行と同じです。

## 告知ページ

告知ページ `/notices` は、止めた版の一覧を示します。侵害が起きたときに、影響を受けた版と期間を利用者に知らせるためのページです。運用の手順は [侵害の対応](../operations/incident-response.md) に記載します。

| 項目 | 内容 |
| --- | --- |
| プラグイン | プラグインの名前と、詳細ページへのリンク |
| 版 | 止めた版のタグ |
| 配布物の SHA-256 | 止めた版の配布物ごとの名前と SHA-256 |
| 掲載の期間 | 本サービスで配布物を掲載していた期間。開始と終了の日時 |
| 告知の文 | 管理者が書いた告知の文 |

止めた版は、止めた日時の新しい順に並べます。告知ページへのリンクはフッターに置き、サイトマップにも載せます。

止めた版と告知の文は `release_suspensions` から、配布物と掲載の期間は `listing_periods` から求めます。表の定義は [データモデル](data-model.md) に記載しています。

## 検索エンジンと共有のときの表示

検索エンジンに各ページを正しく収集させ、英語で検索した利用者に英語のタイトルと説明を見せるため、各ページの head に次を出します。

| 項目 | 内容 |
| --- | --- |
| title | 「<ページの名前> - <サイト名>」。詳細ページのページの名前は「<プラグインの名前> - OBS Studio プラグイン」(画面の言語で表す)。英語で検索した利用者に、OBS Studio のプラグインのページだと分かるようにするため。サイト名は en・pt-BR・es-419 では「Plugin Soko-kun」、ja・zh-Hans・zh-Hant・ko では「配信プラグイン倉庫くん (Plugin Soko-kun)」 |
| description | トップと一覧ではサービスの説明文 (7 言語)。詳細ページでは画面の言語の概要 (訳が無ければ原文) を、改行と連続する空白を 1 つの空白にまとめ、160 文字までに切り詰めたもの。固定ページでは本文の最初の段落。掲載中以外の詳細ページでは注意書き |
| canonical | 表示している言語の `?lang=` を付けた URL。クエリは `lang`・`category`・`page` だけを残し、ほかのクエリと原文の表示 `?orig=1` は外す |
| hreflang | canonical と同じ規則で作った 7 言語の URL と `x-default` (英語版) |
| robots | 検索語 `?q=` と OS の絞り込み `?os=` を含むページは `noindex` にする。URL の組み合わせが無数にでき、同じ内容が重なるため |
| OGP と Twitter card | `og:title`・`og:description`・`og:url` (canonical と同じ)・`og:type`・`og:site_name`・`og:locale`・`og:image` と `twitter:card` |
| 構造化データ | トップに、全言語で同じ内容の WebSite の JSON-LD を出す。`name` は「配信プラグイン倉庫くん」、`alternateName` は「Plugin Soko-kun」。検索結果のサイト名は 1 サイトに 1 つだけ表示されるため。掲載中のプラグインの詳細ページには、SoftwareApplication の JSON-LD を出す。内容は次の表のとおり |

詳細ページの SoftwareApplication の JSON-LD には、次の値を入れます。値の無い項目は出しません。

| 項目 | 値 |
| --- | --- |
| `name` | プラグインの名前 |
| `description` | description と同じ概要 |
| `applicationCategory` | `MultimediaApplication` |
| `applicationSubCategory` | カテゴリの英語の名前 |
| `operatingSystem` | 対応 OS の英語の名前 |
| `softwareVersion` | 掲載対象バージョンのタグ |
| `softwareRequirements` | `OBS Studio <ビルドに使った OBS の版>`。版が無ければ `OBS Studio` |
| `license` | `https://spdx.org/licenses/<SPDX ID>` |
| `url` | canonical と同じ URL |
| `downloadUrl` | GitHub のリリースのページの URL |
| `image` | プラグインのロゴの URL |
| `author` | 作者の GitHub のアカウント名と、GitHub のプロフィールの URL |
| `offers` | 価格 0 (`price` は `0`、`priceCurrency` は `USD`)。本サービスと GitHub での入手が無料であるため |

`og:image` は、ロゴとサービス名を並べた 1200 x 630 px の共通画像 (`/og.png`) で、`twitter:card` は `summary_large_image` です。ロゴがあるプラグインの詳細ページでは、`og:image` をプラグインのロゴにし、`twitter:card` を `summary` にします。`og:locale` は `ja_JP`・`en_US`・`zh_CN`・`zh_TW`・`ko_KR`・`pt_BR`・`es_LA` です。

サイトマップには、トップ・全固定ページ・掲載中のプラグインの詳細ページを、7 言語の `?lang=` を付けた URL で載せます。言語の代替の関係はページ内の `hreflang` で示し、サイトマップには重ねません。JSON-LD は実行されないデータなので、スクリプトを使わない方針と CSP のままで出せます。出すときは `<` を `<` に置き換え、`script` の外へ文字が出ないようにします。

## サービスのロゴ

サービスのロゴは、丸いバッジに図形で描いた「庫」の字です。まだれの左払いをコードに見立て、先端をコンセントのプラグにしています。色は主の色と副の色だけを使い、暗い背景でも輪郭が見えるよう、外縁に主の色を明るくした細い縁を付けます。字は書体に頼らず図形で描くため、表示する環境で形が変わりません。

ロゴは SVG で `/logo.svg` から配信し、上部の帯のサービス名の左と、ブラウザーのタブのファビコンに使います。上部の帯では 40 px 四方で表示し、代替テキストは空にします。サービス名を隣に表示するためです。SVG から作った 256 px 四方の PNG を `/logo.png` から配信し、MCP の `serverInfo` と公式 MCP Registry の `server.json` のアイコンに、SVG と並べて載せます。

## プラグインの画像

プラグインには、ロゴと説明の画像を 1 枚ずつ掲載できます。作者は画像をリポジトリに置き、本サービスは同期のときに取得して自分のドメインから配信します。取得の規則は [検査と同期](scanning.md) に、配信の判断は [ADR 0011](../decisions/0011-plugin-images-hosted-by-worker.md) に記載しています。

| 項目 | ロゴ | 説明の画像 |
| --- | --- | --- |
| 表示する場所 | カードと詳細ページの見出し | 詳細ページの見出しの下 |
| 表示の大きさ | カードでは 48 px 四方、詳細ページでは 64 px 四方に収める | 本文の幅に収める |
| 代替テキスト | 空にする。名前を隣に表示するため | 「<名前> の説明の画像」 |

画像には `width` と `height` を指定し、読み込みの前後で配置がずれないようにします。カードの画像は、画面に入るまで読み込みを遅らせます。

説明の画像は、定期処理が作った表示用の WebP の画像 (`/plugins/<owner>/<repo>/preview`) で表示します。作り方は [検査と同期](scanning.md) に記載しています。

| 元の画像 | 表示 |
| --- | --- |
| PNG・JPEG・WebP | 表示用の画像を表示する。表示用の画像がまだ無いときは、元の画像を表示する |
| GIF | `<details>` で表示する。閉じているときは、`<summary>` の中に、表示用の画像 (最初のコマの静止画) と「▶ アニメーションを再生」の文字を重ねる。開くと、`loading="lazy"` を付けた元の GIF を表示し、静止画を隠す。表示用の画像がまだ無いときは、静止画の代わりに灰色の網掛けを表示する |

閉じた `<details>` の中の画像は、`loading="lazy"` を付けると開くまで読み込まれません。2026-11-11 に Chrome 157 で確かめました。`loading` を指定しない画像は、閉じていても読み込まれました。Firefox と Safari では確かめていません。GIF は利用者が開いたときだけ再生するため、閲覧者が望まない動きを最初から見せません。
