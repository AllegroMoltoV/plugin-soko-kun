# ADR 0017: Cloudflare Workers の有料プランを続ける

- 状態: 採用 (2026-11-15)
- 改める判断: [ADR 0001](0001-hosting-cloudflare-workers-free.md) の、Cloudflare Workers の無料プランを使う判断

## 背景

ADR 0001 では、固定費を避けるため Cloudflare Workers の無料プランを使い、上限に達した時点で有料プラン (Workers Paid) への切替えを検討することにしました。2026-11-15 に、Workers AI の 1 日の無料枠を超えてレビューを続けるため、アカウントを 1 か月だけ有料プランに切り替えました。

無料プランに戻す前に、本番の Worker の CPU 時間を測りました。非公開の検証記録では、直近 24 時間の定期処理 96 回の CPU 時間は中央値 46 ms・最大 121 ms でした。要求は、種類ごとの中央値が 13〜29 ms でした。無料プランの CPU 時間の上限は、要求 1 件・Cron Trigger 1 回ともに 10 ms です。Cloudflare の公式の文書 ([Workers の上限](https://developers.cloudflare.com/workers/platform/limits/)) は、まれな超過には余裕を持たせる一方で、一貫して上限を超える Worker は上限に従って打ち切ると書いています。

## 決定

Cloudflare のアカウントを、Workers Paid のまま続けます。費用は、アカウントの最低料金の月 5 USD です。本サービスの使用量は、有料プランに含まれる要求と CPU 時間の量を大きく下回ります。Workers AI の費用は、AI Gateway の支出の上限で止めます ([アーキテクチャ](../design/architecture.md))。

コードは、本サービスが 1 回の起動に設ける予算 (外部呼び出し 45 件、D1 のクエリ 45 件) と読み込みの上限の内で動作させ、有料プランの上限に合わせて広げません。CPU 時間の 10 ms は前提にしません。

## 検討した選択肢

| 選択肢 | 判断 |
| --- | --- |
| 有料プランを続ける | 採用しました。CPU 時間の上限が既定で 30 秒になり、定期処理と要求が打ち切られません。同じアカウントの姉妹版の音のプラグイン倉庫くんとほかの Worker も同じ条件で動作します |
| 無料プランに戻し、処理を 10 ms の内に収まるよう作り直す | 採用しませんでした。定期処理を 1 回あたり 10 ms に収めるには処理を細かく分ける必要がありますが、アカウントの Cron Trigger は 5 個すべてを使っており、分ける手段がありません。画面の描画の CPU 時間も削る必要があり、収まる見込みが立ちません |
| 無料プランに戻し、打ち切られたら有料プランに戻す | 採用しませんでした。打ち切られると、気づいて戻すまでの間、カタログと検査が止まります |

## 影響

ADR 0001 の、無料プランを使う判断を改めます。無料プランの上限から導いた設計は保ちます。配布物を Worker でダウンロードしない判断 ([ADR 0003](0003-github-digest-without-download.md))、検査を Cron で進める判断 ([ADR 0007](0007-asynchronous-scanning-with-cron.md))、証明の署名を GitHub Actions で検証する判断 ([ADR 0014](0014-attestation-verification-in-actions.md)) です。外部呼び出しの予算と読み込みの上限は、GitHub のレート制限と費用を抑える役目も持ち、作り直す利点が無いためです。

有料プランでは、Workers AI の 1 日の無料枠を超えてもレビューが止まりません。レビューを止めるのは、主に AI Gateway の支出の上限です。KV の別のキーへの書き込みには 1 日の上限がなくなるため、OAuth の経路のレート制限は、費用と乱用を抑えるために保ちます。
