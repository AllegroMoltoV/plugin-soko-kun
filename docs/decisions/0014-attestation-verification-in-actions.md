# ADR 0014: 証明の署名の検証を GitHub Actions で行い、結果を OIDC のトークンで受け取る

- 状態: 採用 (2026-11-13)

## 背景

[ADR 0013](0013-release-provenance-and-review.md) で、新しい版のすべての配布物の build provenance の証明を、署名まで検証することにしました。2026-11-13 に、Sigstore の公式の検証ライブラリ `@sigstore/verify` を Worker で動かして測ったところ、検証 1 件の CPU 時間は 24〜45 ms でした。Workers の無料プランの上限は、1 回の起動あたり 10 ms です。

## 決定

本サービスのリポジトリに、証明を検証するワークフロー `.github/workflows/verify.yaml` を置きます。ワークフローは 15 分ごとに動き、次の順で処理します。

1. GitHub Actions の OIDC のトークン (`aud` は `soko-kun`) を添えて、Worker から検証待ちの配布物の一覧を受け取る
2. 配布物を取得し、GitHub の公式の CLI の `gh attestation verify` で、リポジトリ・タグ・タグのコミット・リリースのワークフローを指定して検証する
3. 結果を、同じく OIDC のトークンを添えて Worker に送る

Worker は、GitHub が公開する鍵でトークンの署名を確かめ、`iss`・`aud`・`repository`・`job_workflow_ref` (本サービスのリポジトリの main の `verify.yaml`)・`exp` を照合してから、一覧を返し、結果を受け付けます。この検証の CPU 時間は、2026-11-13 の測定で 1 件 0〜3 ms でした。

## 検討した選択肢

| 選択肢 | 判断 |
| --- | --- |
| Workers の有料プランに移り、Worker で検証する | 採用しませんでした。月 5 USD の固定の費用がかかるためです |
| Durable Objects で検証する | 採用しませんでした。公式の文書で CPU 時間の上限の記述が食い違い、無料プランで収まる根拠が得られないためです |
| 署名を検証せず、GitHub の API が返す証明の内容を信じる | 採用しませんでした。依頼者が署名まで検証することを決めているためです |
| 署名の検証を WebCrypto で自前に書く | 採用しませんでした。検証をすり抜けられる不具合を作り込むおそれが大きいためです |

## 影響

結果を受け付ける口が Worker に増えます。受け付けるのは、本サービスのリポジトリの main で動く `verify.yaml` のトークンだけです。保存しておく鍵はありません。

ワークフローが止まると、配布物は検証待ちのまま掲載されません。GitHub の定期実行は遅れることがあり、リポジトリに 60 日間の活動が無いと止まります。管理者は、確認待ちの一覧に検証待ちの版が溜まることで、止まったことに気づけます。
