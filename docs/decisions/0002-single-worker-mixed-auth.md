# ADR 0002: 認可サーバーと MCP の同居と認証混在

- 状態: 採用
- 決定日: 2026-11-09

## 背景

MCP のツールのうち、`search_plugins` と `get_plugin` は誰でも使えるようにします。`submit_plugin` だけは、登録者が対象リポジトリの管理者であることを確かめる必要があります。そのため、GitHub での本人確認を伴う認証を要求します。

MCP の認可の仕様は、MCP サーバーが自分宛てに発行されたトークンだけを受け付けることを求めています。GitHub が発行したトークンは本サービス宛てではないため、そのまま受け付けられません。

## 決定

1 つの Worker に、OAuth の認可サーバーとリソースサーバーを同居させます。認可サーバーは利用者の本人確認を GitHub OAuth App へ委譲し、本サービス宛てのアクセストークンを発行します。実装には `@cloudflare/workers-oauth-provider` の `OAuthAuthorizationServer` と `OAuthResourceServer` を使います。

MCP のエンドポイントは `/mcp` の 1 本にし、認証混在にします。`Authorization` ヘッダーを持つ要求と、`submit_plugin` を呼び出す要求をリソースサーバーへ渡します。呼び出すツールは `Mcp-Name` ヘッダーで判定し、このヘッダーを送らない旧版のクライアントには要求の本文で判定します。それ以外の要求は認証なしで処理します。

未サインインの `submit_plugin` には 401 を返し、MCP クライアントにサインインを促します。利用者が手動でサインインした後に `submit_plugin` が成功する形を、合格の水準とします。

クライアントの登録方式は、CIMD と DCR の両方を有効にします。

## 検討した選択肢

| 選択肢 | 評価 |
| --- | --- |
| 1 つの Worker に同居させ、`/mcp` 1 本で認証混在にする | 採用しました。非公開の検証記録で、Claude Code が未サインインで `search_plugins` を呼び出せることを確かめました。サインイン後に `submit_plugin` が成功することも確かめました。 |
| エンドポイントを検索用と登録用の 2 つに分ける | 確実に動く構成です。一方で、登録する人は MCP サーバーを 2 つ追加する必要があります。認証混在が検証で動いたため、採用しませんでした。 |
| GitHub を認可サーバーとして直接指定する | GitHub のトークンは本サービス宛てではありません。トークンの audience の検証を満たせないため、採用しませんでした。 |
| 認可サーバーを別の Worker や外部サービスに置く | 構成要素が増えます。同居で要件を満たせたため、採用しませんでした。 |

## 影響

ツール名の判定を自前で実装します。`Mcp-Name` ヘッダーと本文のツール名が食い違う要求は拒否します。認証なしで処理する MCP ハンドラには `submit_plugin` を登録しません。

対話モードの Claude Code が 401 を受けて自動でサインインへ進む動作は、確認していません。Codex のサインインの通し確認は、本番公開時に行います。

認可の流れとエンドポイントの一覧は [認証と認可](../design/auth.md) に記載します。
