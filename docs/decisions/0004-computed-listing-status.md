# ADR 0004: 掲載状態の算出

- 状態: 採用
- 決定日: 2026-11-09

## 背景

プラグインの掲載状態は、管理者の停止操作・GitHub での削除や非公開化・配布物の検査結果の 3 つで決まります。このうち検査結果と GitHub の情報は Cron の同期と検査で更新され、停止操作は管理用スクリプトで更新されます。

掲載状態を列に保存すると、更新の経路ごとに状態を書き換える処理が必要になります。同期と停止操作が同時に走ると、後から書いた側の値が残ります。その結果、停止したプラグインが同期で掲載中に戻るおそれがあります。要件は、掲載停止したプラグインが自動同期で再公開されないことを求めています。

## 決定

掲載状態はデータベースに保存せず、問い合わせのたびに算出します。算出の入力は、プラグインの `admin_suspended` と `removed`、リリースと配布物、配布物ごとの検査結果です。

算出は副作用のない関数 1 つにまとめます。Web・MCP・同期は、この関数の結果だけを参照します。

停止の解除は `admin_suspended` を 0 に戻すだけにします。解除後の状態は算出の結果に任せます。

## 検討した選択肢

| 選択肢 | 評価 |
| --- | --- |
| 状態を保存せず、毎回算出する | 採用しました。状態を書き換える経路が無いため、同期が停止を上書きすることはありません。算出規則を 1 か所でテストできます。 |
| 状態を列に保存し、更新のたびに書き換える | 一覧の問い合わせは単純になります。書き換えの経路が複数になり、競合時に停止が失われるおそれがあります。 |
| 状態を列に保存し、停止中は同期が書き換えない条件を加える | 競合は防げます。算出規則が書き換えの条件と列の値に分散し、両者の食い違いを検出しにくくなります。 |

## 影響

一覧の問い合わせでは、プラグインごとにリリースと検査結果を読み込みます。D1 のクエリの件数は無料プランの予算に収める必要があります。

停止の解除で掲載中に戻るのは、算出の条件を満たす場合だけです。マルウェアが検出されたリリースがあれば、管理停止を解除しても停止のまま残ります。

算出の規則は [データモデル](../design/data-model.md) に記載します。
