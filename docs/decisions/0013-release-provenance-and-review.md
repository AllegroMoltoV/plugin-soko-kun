# ADR 0013: 新しい版の掲載に、証明・不変・差分の検査・開発の実践のレビューを加える

- 状態: 採用 (2026-11-13)
- 改める判断: [ADR 0004](0004-computed-listing-status.md) (算出の入力を加える)、[ADR 0005](0005-malwarebazaar-not-found-as-clean.md) (掲載中の配布物を照会し直す)

## 背景

2026-03 に、OBS Forums で作者のアカウントが乗っ取られ、掲載中のプラグインの配布物が悪意のある版に差し替えられる事件が起きました。本サービスは配布物を預からず、GitHub のリリースへ案内します。そのため、差し替えの防御は、GitHub が記録する事実のうち何を掲載の条件にするかで決まります。

これまでの掲載の条件は、配布物の SHA-256 が MalwareBazaar に収録されていないことだけでした。この条件では、乗っ取ったアカウントで上げた未知のマルウェアの新しい版を止められません。

## 決定

新しい版を掲載する条件に、次を加えます。

1. 掲載の条件: すべての配布物に build provenance の証明があり、その署名と内容が、このリポジトリ・そのタグ・そのタグのコミット・記録したリリースのワークフローに一致する。リリースが不変である。配布物に exe や msi のインストーラーが無い
2. 乗っ取りの兆候: 掲載中の版からの差分で、リリースのワークフローの変更・バイナリの追加・別のホストへのリンクの追加・24,000 文字の超過に当たる版は、管理者の確認待ちにする
3. 開発の実践のレビュー: LLM が [審査の基準](../design/review-criteria.md) にしたがってリポジトリを読み、指摘を作者に返す。重大な指摘がある版は、管理者の確認待ちにする
4. 掲載中の配布物を、MalwareBazaar へ定期的に照会し直す

署名 (Authenticode、Developer ID) は条件にしません。個人の作者には費用の負担が大きく、誰でも載せられる本サービスの考え方と両立しないためです。推奨として作者に返します。

掲載の可否を LLM に決めさせません。LLM の判定は揺れがあるためです。決定的な判定はルールで行い、LLM はルールで判定しにくい開発の実践を読む役に限ります。

条件を加えた時点で掲載中の版には、新しい条件を当てません。

## 検討した選択肢

| 選択肢 | 判断 |
| --- | --- |
| LLM に新しい版の差分を読ませ、悪意のある変更を見抜かせる | 採用しませんでした。公開の報告書から取った悪意の例では、検出の理由が中身ではなく周辺のリンクに頼る例があり、見抜く力に確かな根拠が得られませんでした (2026-11-13 の検証) |
| 署名を掲載の条件にする | 採用しませんでした。Windows の署名は、日本の個人には年 200 USD 程度の証明書が要り、多くの作者が載せられなくなります |
| 新しい版を一定の時間寝かせてから掲載する | 採用しませんでした。証明と不変のリリースで差し替えの経路を閉じるため、重ねる意味が小さいためです |
| 作者が新しい版の掲載を申請する | 採用しませんでした。新しい版を自動で取り込む今の設計の単純さが失われるためです |

## 影響

掲載状態の算出の入力に、証明の検証の結果、リリースの不変、差分の検査の結果、レビューの結果、管理者の承認と版の停止が加わります。算出は ADR 0004 のとおり副作用の無い関数で行います。

エンドユーザーには掲載中の版だけを示し、確認待ちの版とその理由は示しません。理由と直し方は、作者の LLM に MCP で返します ([作者へのレビューの返し方](../design/author-feedback.md))。

証明の署名の検証は Worker の CPU 時間の上限に収まらないため、GitHub Actions で行います ([ADR 0014](0014-attestation-verification-in-actions.md))。

侵害が起きたときの手順は [侵害の対応](../operations/incident-response.md) に記載します。
