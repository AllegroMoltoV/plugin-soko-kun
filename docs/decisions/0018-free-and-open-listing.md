# ADR 0018: 掲載を、オープンソースのライセンスで無料で入手できる版に限り、料金と素材の条件は作者の申告で示す

- 状態: 採用 (2026-11-19)
- 関係する判断: [ADR 0013](0013-release-provenance-and-review.md) の、新しい版の掲載の条件

## 背景

本サービスは、作者が GitHub の公開のリリースに添付した配布物へ案内します。配布物は GitHub から直接ダウンロードし、本サービスは保管しません。

これまでの掲載の条件は、登録の時点で GitHub がリポジトリのライセンスを検出できることだけでした。ライセンスの種類は問わず、版ごとにも判定していませんでした。そのため、利用者には、プラグインの有料と無料の別、商用利用の可否が分かりませんでした。作者には、本サービスでの有料の販売の可否と、ライセンスの付け方が分かりませんでした。外部の有料の API を使うプラグインでも、その事実は概要の文でしか伝わりませんでした。

姉妹版の音のプラグイン倉庫くんは、版ごとに、タグの時点のライセンスが OSI の承認か FSF の自由の認定を持つことを掲載の条件にしています。OBS Forums の Forum Resource and IP Policy は、OBS のプラグインが GPL v2.0 以降に従い、ソースを公開する必要があるとしています。

## 決定

掲載するのは、GitHub の公開のリリースから無料で入手でき、検査を通った配布物だけです。配布物の導線と検査の仕組みは変えません。

掲載の条件に `open-source-license` を加えます。コードのライセンスが、版のタグの時点で OSI の承認か FSF の自由の認定を持つことです。満たさない版は掲載しません。この条件は、検査の前提を持たない旧い版 (legacy) にも当て、管理者の承認でも外しません。判定の手順は [検査と同期](../design/scanning.md) の「ライセンスの判定」に記載します。

有料の販売は、次の 3 つの型で扱います。

| 型 | 内容 | 扱い |
| --- | --- | --- |
| 型A | 同じ配布物を GitHub で無料で公開し、外部での販売や寄付の受け付けも行う | 掲載する |
| 型B | 一部の機能を、作者への支払いで解放する | 掲載する。`paidFeatures` で申告してもらう |
| 型C | ソースを公開せず、有料の配布物だけを配る | 掲載しない |

料金と利用の条件は、宣言ファイル `.soko-kun/config.json` の任意の 4 項目で作者に申告してもらいます。項目は、作者への支払いで解放する機能の有無 (`paidFeatures`)、利用者が別に契約する有料のサービスの名前 (`paidServices`)、同梱の素材の利用の制限の有無 (`restrictedAssets`)、作者の支援や購入のページ (`supportUrl`) です。項目の形は音のプラグイン倉庫くんと同じにします。

申告は作者によるものです。運営者は申告の内容を確かめません。画面と MCP の応答では、本サービスが確かめた事実と作者の申告を分けて示します。確かめた事実は、入手が無料であることと、ライセンスとその判定の結果です。申告の項目の値が誤っていても掲載は止めず、その項目を申告なしとして扱います。誤りは、作者に固定のコードの注意として返します。

利用規約は変えません。

## 理由

型C を対象外にするのは、購入の前に中身を検査できないためです。本サービスの検査は、公開のリリースの配布物とリポジトリのファイルを対象にします。有料の配布物だけを配る版では、利用者が受け取るファイルを検査に回せません。証明・差分・レビューの仕組みも、ソースが公開されていることを前提にしています。

ライセンスの条件を版のタグの時点で判定するのは、配布物がそのコミットから作られるためです。既定のブランチの現在のライセンスでは、過去の版の配布物の条件を表せません。

料金と素材の条件を作者の申告にするのは、本サービスの入力からは確かめられないためです。レビューが読むのは README とワークフローとビルドの設定で、ソースの全体と同梱の素材の中身は読みません。そのかわり、README の記述と申告の食い違いを推奨の項目 `pricing-declaration` として作者に返します。

申告の誤りで掲載を止めないのは、申告が任意の項目であり、誤りが利用者の安全に関わらないためです。

利用規約を変えないのは、既存の作者の義務「虚偽の情報を掲載しないこと」が申告にも当たるためです。

## 検討した選択肢

| 選択肢 | 判断 |
| --- | --- |
| 掲載の条件と表示を分ける。ライセンスは掲載の条件にし、料金と素材は申告で示す | 採用しました |
| 表示だけを足し、ライセンスの種類は掲載の条件にしない | 採用しませんでした。OSI の承認も FSF の自由の認定も持たないライセンスの版が載り、利用者が商用利用と再配布の条件を判断できないためです |
| 型C を、外部の販売先へのリンクだけで掲載する | 採用しませんでした。購入の前に中身を検査できず、検査を通った配布物だけを案内する方針と合わないためです |
| 申告の誤りで掲載を止める | 採用しませんでした。任意の項目の書き損じで、条件を満たした版の掲載が止まるためです |

## 影響

マイグレーション `0015` で、`release_checks` に `license_state`・`license_spdx`・`declarations` の 3 列を足しました。既存の行には、版のコミットについて GitHub が検出したライセンスを、版ごとの固定値として書きました。列の意味は [データモデル](../design/data-model.md) に記載します。

新しい版の検査の外部呼び出しが 1 件増えました。1 回の起動の予算に収めるため、MalwareBazaar の 1 回の起動の照会の上限を 10 件から 9 件にしました。

作者への応答に、理由のコード `license_pending`・`no_license`・`license_unrecognized`・`license_not_open` と、掲載を止めない注意 `notices` を足しました。応答の形は [作者へのレビューの返し方](../design/author-feedback.md) に記載します。

申告に頼る次の 4 点は、本サービスの手当てでは解消できない限界として受け入れます。申告されなかった有料の機能・外部の有料サービス・素材の制限があること、外部のサービスの規約、プラグインが出力するものの権利、法的な保証です。
