# ADR 0016: 開発の実践のレビューを、項目ごとにルールと LLM に分け、ルールの事実を LLM に渡す

- 状態: 採用 (2026-11-14)
- 改める判断: [ADR 0013](0013-release-provenance-and-review.md) の決定 3 (LLM が審査の基準にしたがってリポジトリを読む)

## 背景

ADR 0013 では、審査の基準と推奨の 16 項目を、1 回の LLM の呼び出しでまとめて判定していました。2026-11-14 に依頼者の 8 本の新しい版を本番でレビューし、次の誤りを確かめました。

- 項目の文が否定の形のとき、結果が説明と逆になった。README がセキュリティの機能を切らせていないと説明しながら、満たさないと判定した
- ソースのコードを読まないのに、コードで判定する項目を判定し、本によって判定不能と満たさないに分かれた
- 指示文で対象外と書いたビルド用の依存を、同梱の第三者のバイナリとみなした
- 同じライセンスと依存のリポジトリで、ライセンスの両立の判定が分かれた。OBS Studio を GPL-2.0 だけとする誤った前提で判定した例もあった。libobs のソースの見出しは GPL-2.0 またはそれ以降である

項目を判定に要るもので分けると、性質の違う 3 種類が混ざっていました。ファイルを見れば機械的に決まる項目、入力に無い知識が要る項目、文章の意図を読む項目です。機械的に決まる項目を LLM に任せると、呼び出しごとに結果が揺れます。入力に無い知識が要る項目では、LLM が足りない知識を思い込みで埋めます。指示文の手直しでは、どちらも防げません。

## 決定

1. 機械的に決まる項目はルールで判定する。同じリポジトリには同じ結果を返し、根拠のファイルと行を示す
2. 文章の意図を読む項目だけを LLM が判定する。対象は `no-security-bypass`・`user-data-handling`・`ci-scenario-tests`・`crash-report-privacy` (テンプレートがあるとき) である
3. LLM には、ファイルの一覧と中身から本サービスが計算した事実を渡す。テンプレートとスクリプトの名前、README の見出しと URL のホストと行番号、ルールの判定の結果である
4. 入力に無い知識が要る項目 (`license-compatibility`・`third-party-provenance`・`license-notices` と、ソースのコードを読む項目) は判定しない。材料を確実に得られるようになったら判定に戻す。`ci-source-build` は掲載の条件の `attestation` で確かめるため判定しない
5. レビューの入力は、ファイルの一覧を 1 回で取り、一覧にあるファイルだけを取得する

項目ごとの判定の方法と基準は [審査の基準](../design/review-criteria.md) に記載します。

## 検討した選択肢

| 選択肢 | 判断 |
| --- | --- |
| 項目ごとに指示文と事実を足し、1 回の LLM の呼び出しで全部を判定し続ける | 採用しませんでした。誤りの原因が判定の方法の選び方にあり、項目を変えて同じ種類の誤りが出続けるためです |
| LLM に道具 (function calling) を渡し、必要なファイルを自分で取得させる | 採用しませんでした。モデルは対応していますが、道具を呼ぶたびに会話の全体を付けて呼び直すため、Workers AI の無料枠の消費が数倍になり、1 回の起動の外部呼び出しの上限に当たります。リポジトリの内容から道具を呼ばせる攻撃の入り口も増えます。各項目に要るファイルと事実は前もって決まるため、本サービスが集めて渡せば足ります |
| LLM のレビューをやめ、ルールだけにする | 採用しませんでした。README でセキュリティの機能を切らせる手順のように、文章の意図を読まないと判定できない項目と、その重大の判定を失うためです |

## 影響

LLM に渡す入力が短くなり、1 件のレビューの Workers AI の消費が減ります。外部呼び出しの件数は、無いファイルを取得しなくなるため、最悪の場合でも変わりません。

ルールで判定する項目の指摘は、explanation も本サービスの固定の文になります。作者に返す notes で、ルールの指摘と LLM の指摘を区別します。

`user-data-handling` は README とワークフローから分かる範囲で判定し、重大の判定を持ちません。ソースのコードの通信を機械的に検出する仕組みを入れたら、その結果を事実として LLM に渡し、重大の判定を戻します。
