# ADR 0003: 配布物の digest の取得方法

- 状態: 採用
- 決定日: 2026-11-09

## 背景

本サービスは、配布物ごとに SHA-256 を記録します。記録した値は、配布物の差替えの検出と、マルウェアのデータベースへの照会に使います。

SHA-256 を自ら計算するには、Worker で配布物をダウンロードする必要があります。無料プランの CPU 時間の上限は、1 回の起動あたり 10 ms です。非公開の検証記録では、1.4 MB の配布物を取得して破棄するだけで 17〜31 ms の CPU 時間を使いました。50 MB では 564〜593 ms でした。

GitHub は、リリースの配布物ごとに SHA-256 の値を `digest` として API で返します。

## 決定

SHA-256 は再計算せず、GitHub が返す `digest` を記録します。マルウェアのデータベースへの照会にも、この値を使います。Worker は配布物をダウンロードしません。

`digest` を持たない配布物は、検査できないため掲載しません。`digest` を持つ配布物が 1 件も無いリリースは、`submit_plugin` で拒否します。

配布物の差替えは、配布物の ID と `digest` の変化で検出します。新しいアセット ID、または `digest` の変化を検出したら、同じ `digest` の過去の結果があっても検査し直します。既知の配布物は、ダウンロード数の変化などでリリースの ETag が変わっても検査し直しません。

## 検討した選択肢

| 選択肢 | 評価 |
| --- | --- |
| GitHub の `digest` を記録する | 採用しました。配布物の取得が不要になり、外部呼び出しは配布物 1 件あたりの照会だけで済みます。照会は Cron で行うため、`submit_plugin` の外部呼び出しは配布物の数によらず最大 6 件です。 |
| Worker でダウンロードして SHA-256 を計算する | 無料プランの CPU 時間の上限を超えます。GitHub の値と自前の値を照合できる利点はあります。 |
| ダウンロードとハッシュ計算を外部の実行環境に任せる | 構成要素が増えます。要件の YAGNI の方針に反するため、採用しませんでした。 |

## 影響

記録した `digest` の正しさは GitHub に依存します。本サービスは、GitHub の値と配布物の実体が一致することを独自には確かめません。

ハッシュの記録だけでは、利用者がダウンロードしたファイルが検査したものと同一であることを保証できません。Web カタログには `digest` を表示し、利用者が手元で照合できるようにします。

ダウンロード URL は GitHub の配布物へ直接リンクします。本サービスは配布物を保持しません。
